# 记忆系统与主人主线程行为规则

长期记忆按 `owner`、群聊、私聊分别存放；自动抽取、显式工具与管理台共用存储规则。管理操作只作用于所选会话，不把跨会话搜索结果混入模型上下文。

## 1. 条目、画像与遗忘

- **有效期与召回**：默认召回只返回当前有效条目；`mem_search history=true` 可查过期或尚未生效条目。经历的结束日期表示事件结束，不代表被遗忘。
- **去重边界**：精确去重同时核对对象；经历核对发生区间，承诺核对截止时间。已过期条目不阻止重新记入当前事实；整理使用相同的身份边界。
- **遗忘与抑制**：遗忘是可恢复的状态修改，保留历史版本。相同对象、类型与规整正文的已遗忘条目会阻止后台自动重新写入；用户显式重新记住或恢复可解除抑制。
- **画像与复核**：保存画像时关联当前有效记忆；关联条目被更正、替代、遗忘或失效后，画像暂停进入模型提示，正文保留供复核。人工保存或采纳建议会重新确认证据；采纳时同时核对画像版本与来源内容指纹。
- **未完成承诺**：独立于画像展示；记录截止时间不会自动创建定时提醒。

## 2. 自动抽取与冲突处理

- 抽取提示给出每条用户消息的 ID，候选必须引用本轮消息且证据片段须存在于对应原文（多条输入缺少来源时不猜测最后一条）。助手回答仅作上下文，助手承诺由显式工具记录。
- 抽取只能替代本次提供给模型、且版本未变化的自动条目；与显式记录冲突时进入待确认列表，确认时再次核对目标版本。人工编辑、确认已有自动条目或恢复历史版本后，条目按显式记录保护。
- 抽取队列使用持久领取租约，临时失败后延迟重试最多三次，超时晚到结果不落库，终态保留收据防重复入队；每日每会话预算 200 次（重试计入预算）。

## 3. 检索与管理界面

- 精确字面搜索优先完整匹配及显式记录，不按历史召回时间持续抬高旧命中；完整问句查不到时回退最多 6 个关键词按共同命中数合并，并明确标记为关键词相关结果。召回事件仅记录条目 ID、数量与降级标记，不记录查询正文。
- 记忆页支持按 ID、类型、状态、有效期、写入方式筛选，以及新增、编辑、完成承诺、遗忘、恢复、整理与批次回滚；详情展示来源、画像关联、替代关系与版本差异。
- 页面请求绑定会话与递增序号，旧响应不能覆盖当前会话；编辑与遗忘携带条目版本；画像编辑在并发冲突时保留草稿并展示当前保存版本供比对，登出时清除草稿。

## 4. 主人主线程行为规则（精确批准与数据库保护）

### 4.1 边界与管理流程

本功能不是权限系统：规则作为行为与回复约定，作用于 `owner` 主线程面向主人私聊的回合——包括主人 QQ 私聊、Web 主人会话、定时任务、外部事件及子任务汇报回合（会影响该回合的任务协作、处理流程与回复方式），不改变工具权限、隐私、安全或发送授权；群聊、项目会话和独立运行的子 agent（`SubagentDO`）不继承。普通 `kind=rule`、`active`、作者来源、正文声称“已批准”或模型工具调用均不代表批准。

管理接口前缀为 `/admin/memory/rules`（除 `scopes` 外均要求 `?ns=owner&scope=private:<已配置主人>`），仅向 Bearer 鉴权管理入口开放，未注册模型工具；管理读操作直接访问 owner DO 真实数据，不读可能滞后的展示副本：

1. 在主人记忆详情打开「规则批准 / 修改 / 撤销」，选择已配置主人的确切私聊，编辑正文与有效期并生成提案预览。
2. 核对精确 JSON 正文、作用域、`memory_version`、`binding_revision` 与 SHA-256。
3. 单独点击「我批准以上精确版本和正文」完成确认；修改同样生成新提案，确认事务原子更新正文与批准。
4. 撤销需携带 `memory_version` 与 `binding_revision`；普通编辑、遗忘、替代、恢复、回滚或维护对受保护条目均被拒绝，必须先显式撤销再遗忘。恢复记忆数据不会复活批准；撤销本身即令画像旧副本进入待复核状态，已受规则管理的条目也不再进入自动画像建议。
5. 超时或结果未知时按原 `requestId` 查询 `/admin/memory/rules/receipts/:requestId` 回执（相同输入幂等返回，不同输入返回冲突）。

前端规则编辑器由 namespace、详情代际、登录代际与 dialog 状态共同限定，内部 scope 请求独立编号，阻止关闭/切换/登出后的迟到响应污染页面或旧控件触发写请求。

### 4.2 一致性、预算与生效机制

- **预算**：每 scope 最多 24 条 `enabled`（含未来/已到期但未撤销条目），每条 500 字，完整编译上限 8,192 UTF-8 字节；超限原子拒绝，不静默截断。
- **强一致直读**：每次 `prepare` 事务直读数据库（不加规则缓存），按 ID 稳定排序，`since <= now < until`，digest 不含墙钟时间，到期无需写库即失效。
- **独立 Pi section**：`memory-rules` 独立于画像渲染；正文 JSON 编码并转义尖括号；相同文本无 patch，最后一条移除产生 `null` patch。写成功为 `committed`，下一次成功 `prepare` 为 `rendered`，在途请求与已准备 cutoff 不被追改。
- **降级与审计**：读库、预算或完整性校验失败时返回明确 `unavailable` 替代块（不抛错避免 Pi 保留旧段）；日志仅记录 `rendered`/`unavailable`、digest、epoch、ID/revision 与字节数，不落规则正文。

### 4.3 数据库触发器与历史标签保护

- 数据库触发器阻断已启用规则条目的所有低层语义修改、删除及 `memory_versions` 直接插入（包括清空 `due_at`/`done_at` 这类产生新版本的写操作；仅召回计数与时间允许更新）。专用批准事务内临时停用对应绑定后更新，失败整体回滚。
- 既有 `memory_imported_versions`、`memory_history_map`、`memory_history_receipts` 表及 `memory_history_append` 视图和 `memory_history:*` / `memory_rule:*` 触发器完整保留，禁止为既有版本补标签、篡改/删除历史标签或历史版本，确保历史版本永远不能冒充当前版本或复活已撤销批准。
- 新增表与触发器独立追加，不修改已部署 DO 的迁移历史；`ThreadDO.alarm()` 第一行仍同步派发已准备好的模型请求。

## 5. 验证覆盖

- `memory-rules.test.ts`：版本/正文 CAS、并发与 ABA、作用域与触发器保护、`14a9465` 旧表真实 `initialize` 升级、`memory_history_append` 原子回滚、历史标签防篡改及真实 Harness 恢复。
- `memory-rules-pi.node.mjs`：锁定 Pi section planner 行为（throw 保旧、稳定无 patch、null 删除、两种 `supportsMidConvoSystemMessages` HTTP payload）。
- `memory-browser.node.mjs`：真实前端模块的乱序响应、版本编辑/遗忘、画像冲突草稿与规则编辑器生命周期隔离。
