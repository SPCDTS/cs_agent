# DO 查询与模型出站隔离

## 最终边界

本方案复用现有 DO 类和绑定，不新增 Queue，也不按模型请求创建 DO。

| 入口或数据 | 负责对象 | 行为 |
| --- | --- | --- |
| QQ、网页发言、定时与事件命令 | ThreadDO；子任务由 SubagentDO 接纳 | 持久化输入，由原对象的 alarm 执行 |
| 每次 OpenAI 模型 HTTP 请求 | 同一个执行 DO 的 ModelAlarm | SDK 完成请求准备后排队，新的 alarm 第一行发出 fetch |
| 请求明细、用量、工具记录、拓扑 | RequestsDO `main` | 保留原有有界采集和查询 |
| 会话管理展示 | RequestsDO `view:thread:<线程>` | 只查询本地展示副本 |
| 子 agent 对话展示 | RequestsDO `view:sub:<父线程>:<子任务>` | 只查询本地展示副本，结束 14 天后清理 |
| 凭据、设置、技能 | RegistryDO | 保留现有权限和认证逻辑 |

展示实例按会话／子任务复用，不按刷新次数或模型请求数创建。RequestsDO 可以接收管理查询，因为它不执行模型；客户端请求不再为了查聊天、历史、事件、记忆、MCP 授权与审批、子 agent 详情、会话状态或健康检查进入执行 DO。展示对象没有向执行对象兜底读取的代码。

管理写命令仍直接进入有权处理它的业务对象。单纯拆开查询不能隔离所有入站事件，所以模型传输层还必须逐次经新 alarm 派发。主 agent 与子 agent 的 Codex 原生接口和旧 Responses 接口都使用这一层；DeepSeek 的传输保持原实现。Registry 的模型目录仍使用其既有 alarm 流程。

## 同步、恢复与成本

执行对象的 SQLite 触发器将展示所需行的新增、修改和删除记入本地变更表，与业务变更同事务提交。同一行尚未确认的多次变化合并；只同步白名单表，不复制凭据、运行任务表、工具恢复状态或完整请求快照。

普通通知合并 150 毫秒内的写入，按至多 100 行分批推送。展示对象在本地事务中更新副本，以源变更序号去重；源对象收到确认后才删除对应变更。同步失败保留数据，并合入原有 alarm 的最近唤醒时间，5 秒后重试。对象重新加载时重新安装检查并补发待同步行。没有新增空闲轮询；主要额外开销是每次模型出站的按需 alarm、变更记账以及展示副本存储。

已有会话由现有每五分钟维护入口回填一次，不由管理员 GET 触发。首次回填全部批次完成后才标为可读；未完成返回 `503 view_pending`，界面显示待同步，工具数未知时不显示为 0。聊天接口和会话状态返回 `syncedAt`，页面显示最近同步时间。正常管理写命令返回前尽力同步结果；展示故障不把已经成功的业务修改改成失败，也不撤销修改。

展示数据是最终一致副本。运行中的变化可能短暂滞后；操作权限、CAS 冲突、任务状态修改和实际执行仍以业务对象为准。常规同步不反复搬运整段历史；一条完整的会话条目只在该行变化时同步。模型请求正文和凭据只在内存中等待新 alarm，不写入同步表。

## 出站约束

`ThreadDO.alarm()` 与 `SubagentDO.alarm()` 的第一行必须调用 `modelAlarm.dispatch()`。此方法同步调用已经准备好的 fetch；在它之前增加配置读取、存储读取或 RPC 的 await，都会破坏验证过的边界。响应头和 SSE 由原 SDK 读取，取消信号继续向上游传播；此层不额外重试模型请求，不改变 QQ 投递和工具恢复规则。

主动出口诊断是执行操作，使用 `POST /admin/diagnostics/model-egress`，继续要求管理员认证；它不是管理页的状态轮询接口。

## 实验依据与限制

2026-11-11 的独立 Cloudflare 实验使用固定工具结果和相同的续轮请求体，确认 Queue 命令实际送达后再发送模型请求。对照流程共 9 次请求：6 次 HTTP 200，2 次 Queue 命令后的续轮与 1 次直接只读 RPC 后的续轮返回 HTML 403；显示库读取后的续轮成功，新 alarm 也恢复成功。改为原执行 DO 内每次通过新 alarm 派发后，同样的干扰流程 9/9 HTTP 200。没有因此引入新的模型 DO 或代理链路。

这说明 Queue 转交命令并不能提供本实验所需的请求上下文隔离。workerd 的实现也表明 actor 共享 IoContext，新的入站请求可以接管当前请求上下文，出站客户端取自该上下文。对应源码见 [io-context.h](https://github.com/cloudflare/workerd/blob/48c9ab1750cb920b11f3e087ef579c00f38ba8fc/src/workerd/io/io-context.h#L1587-L1605)。实验不能证明 OpenAI 私有风控规则的精确触发字段，也不能保证未来所有 403 都能靠这个改动解决。

实验 Worker、Queue 和其 DO 命名空间均已删除。离线检查覆盖主／子 agent 工具续轮、查询不回调执行 DO、历史分页、记忆检索及更新删除、同步失败后的重启补齐；真实线上业务验收仍需在发布后进行。
