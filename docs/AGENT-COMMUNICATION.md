# Agent 通信 MVP

## 身份与接口

运行时注入 agentSessionId：主会话为 owner、group:<群号> 或 private:<用户号>；子会话为 sub:<父会话>:<子 ID>。模型只可调用 agent_send({to,text?,files?})，不能指定来源、用户身份、权限或消息 ID。回复仍用 agent_send。

消息 ID 从来源、会话代次和工具调用 ID 稳定生成。同次调用重放复用原文件快照；accepted/duplicate 只表示原收件箱已收下，不表示已读或任务完成。通信不新增 cancel/wait/delegate/steer 或任务状态机。

## 控制入口（默认关闭跨会话通信）

部署环境变量 AGENT_COMMUNICATION_EDGES 是 JSON 有向边列表，例如：

```json
[["owner","group:200000001"],["group:200000001","owner"]]
```

仅由有部署配置权限的操作者在现有 Worker 配置入口设置；不接受通配符，不读取或复用 QQ send grant。未配置且没有持久授予时拒绝跨主会话通信。双向通信需两条边。群内所有已可使用该群 Agent 的成员共用群会话身份；不是仅对配置者或某次发言人放行。QQ 群准入及触发规则仍独立生效。

主人主线程的交互回合可在 codemode 的 access 分组调用 edge_list、edge_grant 和 edge_revoke。授予与撤销均只对给定方向生效；撤销留下持久 deny，优先于部署基线，重启后仍有效。仅可写精确主会话地址，不接受自环、子会话或通配符。Registry 最多保存 256 条覆盖，保留最近 1024 次变更的 actor 与时间；满额时仍可修改已有边。预留票据、发送和接收端验证分别重新读取权限。

已登记且未撤销的父子会话边使用既有派出关系，无需配置额外边。会话重置使旧来源证明失效。接收主会话需已有当前代次的本地用户上下文，否则返回 agent_recipient_not_ready；不会由陌生通信创建带权限的新会话。

本改动未设置任何生产环境变量。示例群号仅用于说明与测试；实际授权需由获授权操作者另行执行。

## 权限与输出

Thread 使用既有 inbound，Subagent 使用既有 inbox，执行仍经 root.submit，忙时固定 followUp；不创建第二套收件箱。旧 subagent.message 与自动结果汇报使用相同通信服务，spawn/cancel/list 生命周期入口保留。

通信入站使用独立 kind=agent、空 user_id 及可追踪来源，不伪装成 owner 输入。通信边不包含任意 coding 委托：无论群或 owner 的 Agent 回合都不签发或借用人类 SandboxTask，不能据通信任意写文件或执行命令；正常人类群回合及明确派给子任务的原有 coding 能力不受影响；已接收附件可凭当前代次入箱记录经 read 只读和转发，不能读其他主人文件；MCP 使用接收会话主体 agent:<会话地址> 和 kind=agent，不使用最近群发言人的身份。群 Agent 必须在既有 MCP grant 的 actors 中显式加入 agent:group:<群号>，工具、资源、环境及审批策略仍取该 grant；旧数字用户或 * 不自动授予 Agent。owner Agent 同样 owner=false，仅可使用显式 eventAllow 工具白名单；不获得环境或资源访问，写调用仍需审批。代次重置与 grant 撤销即时生效；不继承发送方权限、不写入新 grant。父子通信地址仍绑定会话；不能保持原派出身份的跨成员或 Agent 追问，在写入子 inbox 之前明确拒绝，不能先给运行中的 owner 子任务注入文本再降权。两入口使用同一校验；原任务与原报告不被拒绝的输入污染。

需要用户本人输入的管理、写记忆等操作仍受原入口限制；Agent 回合只能只读本会话记忆。普通 send_message/send_file 不能把 Agent 回合输出发往 QQ/网页。自动子任务结果仍通过原报告格式交回父任务，不会直接通知 QQ。

## 文件

files 是发送方自己已授权工作区的路径列表，最多 5 个，单次总量不超过 10 MiB。宿主读取字节并冻结为来源 R2 资产；接收端验证来源证明和完整资产引用、哈希、大小，不另存接收方 R2 assets，而是以消息 ID + 附件序号生成稳定 operationId，经 saveAttachment 的独立只增附件提交路径（字节 + manifest/head + 原子成功回执）持久化到 /work/agent-files/<消息哈希>/。只在持久提交成功后入箱，目标可用既有 read 读取；接收、读取和转发附件不依赖 coding_exec。子任务即使未授 coding，也只能读取其 inbox 登记的附件。不能用裸跨 scope asset ID 或发送方路径代替副本。

同路径同 SHA 的 createOnly 原本就能以不同操作 ID 成功；不能据此声称随机 ID 必然冲突。附件现在不调用容器命令，不生成 failed/unknown/expired 命令回执；R2 或事务提交前失败可重新提交，head 与成功证明原子更新，不受命令 32 条结果窗口影响。

子会话验证来源与边授权后先查询既有 inbox：相同 ID/信封返回原 duplicate 回执，不重建或覆盖已编辑、已删除的附件；不同信封拒绝冲突。父状态同步失败仍可重试，但不重新导入文件。已回答报告遇到明确会话撤销/结束时沿用 cancelled 状态退休，不增加 reported 计数；投递未知或临时错误保留 answered 和心跳重试。

登录凭据禁止转发。已知凭据文件名和凭据文本模式在完整内容上检查，不先截断；模式检查不是对任意编码/加密文件内容的万能识别，模型仍须遵守不传凭据的约束。

自动汇报保留全文，同时移除原有 reportText 的 8000 字限制和新通道的提前截断；8000 字上限本身不是本 PR 新引入的回归。疑似凭据值明确替换为隐藏提示，不误标整个任务失败。已识别凭据键的 YAML |、>、缩进延续行及完整引号值整体隐藏；引号未闭合而无法判定值边界时保留前文，隔离后文并给出明确提示，不声称隔离内容仍完整可见。凭据模式可能隐藏示例值，仍需人工阅读核验。

纯文本/报告的待投递证明只存输入及信封哈希；附件发送冻结引用与正文，成功后压缩为哈希和回执。发送前先持久占位，再读取或上传源文件，满额拒绝不会先创建未投递资产。已持久工具任务的 startedAt 与工具 memo 票据绑定重试；自动报告将回答时间和票据保存在原有 inbox 行中，不另建无限增长的去重表。接收方代次同时绑定到冻结信封，重置后旧消息不能重新导入附件。

## 验证边界

本地测试使用 workerd/SQLite/R2 测试环境、faux 模型；工作区持久化用真实 WorkspaceManager/manifest/CAS，容器客户端使用测试夹具。它们验证源码链路，不等于真实 Cloudflare 容器、真实账号或线上群部署验收。发布前还需独立审查，并在另行授权的环境验证双方实际 read 文件及无 QQ 外泄。当前不得宣称线上可用。

### 容量与重试生命周期

每代次最多 512 个在途及近期终态证明，不再是累计成功发送上限。满额时，事务仅回收已确认持久入箱的 accepted/duplicate 回执，以及尚未发布证明时确定拒绝的凭据/文件权限/大小错误，尽量回收到半满。准备中、暂时 I/O 失败、投递或回执提交 unknown 均保留；全部 512 项都在途时明确返回 agent_history_full，已有 ID 仍可恢复。成功持续释放名额，无需重置会话或提高常数。

重试窗口按容量而非固定时长计算：纯终态负载通常保留最近约 256–512 份；在途优先时终态窗口可以更短。回收后的原票据返回 agent_message_expired，不重新执行，也不伪称成功。一个常量大小的退役时间水位同时拒绝已过期、尚未占位的旧任务；已存在的在途记录优先匹配，可越过水位继续恢复。同 ID 不同输入在保留期内冲突，回收后统一过期拒绝。任务开始时间必须来自持久宿主记录，不能用每次重试的当前时间替代；时钟回退也保守拒绝未占位的旧时间调用。

旧格式记录可就地绑定票据并恢复；没有 startedAt 的旧工具任务只允许恢复现存证明。新协议启用后，缺失的无票据旧调用明确过期。旧终态无时间戳时，以回收时刻保守推进水位；可能拒绝尚未占位的旧调用，而不是冒险重放。自动报告遇到明确过期或关系撤销，沿用 cancelled 并记录退休诊断，不永久保持 answered；临时错误仍重试。子任务的普通 14 天保留期也不能删除有效父关系下的在途证明或待汇报回答；显式取消或父代次撤销后才可退休。并发完成只更新仍存在的原证明，不复活已经回收的记录。

新信封的附件提交回执只保留到接收方持久入箱：随后由接收方清理，清理失败仍可通过原消息重试。已提交 inbox 的重复请求不再导入文件，所以清理后仍不覆盖编辑、复活删除副本。部分导入/入箱事务失败时绝不释放附件证明；旧信封缺少接收方代次绑定时保守保留原附件回执。普通消息历史、工具记录及实际文件仍遵循各自保留策略，不作为新增无限去重账本。

这些是源码协议及测试边界，不构成线上验收、独立批准或发布授权。
