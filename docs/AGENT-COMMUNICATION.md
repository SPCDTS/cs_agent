# Agent 通信 MVP

## 身份与接口

运行时注入 agentSessionId：主会话为 owner、group:<群号> 或 private:<用户号>；子会话为 sub:<父会话>:<子 ID>。模型只可调用 agent_send({to,text?,files?})，不能指定来源、用户身份、权限或消息 ID。回复仍用 agent_send。

消息 ID 从来源、会话代次和工具调用 ID 稳定生成。同次调用重放复用原文件快照；accepted/duplicate 只表示原收件箱已收下，不表示已读或任务完成。通信不新增 cancel/wait/delegate/steer 或任务状态机。

## 控制入口（默认关闭跨会话通信）

部署环境变量 AGENT_COMMUNICATION_EDGES 是 JSON 有向边列表，例如：

```json
[["owner","group:200000001"],["group:200000001","owner"]]
```

仅由有部署配置权限的操作者在现有 Worker 配置入口设置；不接受通配符，不读取或复用 QQ send grant。不设置则拒绝所有跨主会话通信。双向通信需两条边。群内所有已可使用该群 Agent 的成员共用群会话身份；不是仅对配置者或某次发言人放行。QQ 群准入及触发规则仍独立生效。

已登记且未撤销的父子会话边使用既有派出关系，无需配置额外边。会话重置使旧来源证明失效。接收主会话需已有当前代次的本地用户上下文，否则返回 agent_recipient_not_ready；不会由陌生通信创建带权限的新会话。

本改动未设置任何生产环境变量。示例群号仅用于说明与测试；启用实际群必须由获授权操作者另行配置和发布。

## 权限与输出

Thread 使用既有 inbound，Subagent 使用既有 inbox，执行仍经 root.submit，忙时固定 followUp；不创建第二套收件箱。旧 subagent.message 与自动结果汇报使用相同通信服务，spawn/cancel/list 生命周期入口保留。

通信入站使用独立 kind=agent、空 user_id 及可追踪来源，不伪装成 owner 输入。群 Agent 的 coding 使用独立会话主体任务，不借用最近发言人的任务；owner Agent 不借主人 SandboxTask，不能任意写文件或执行命令；已接收附件可凭当前代次入箱记录经 read 只读和转发，不能读其他主人文件；MCP 使用接收会话主体 agent:<会话地址> 和 kind=agent，不使用最近群发言人的身份。群 Agent 必须在既有 MCP grant 的 actors 中显式加入 agent:group:<群号>，工具、资源、环境及审批策略仍取该 grant；旧数字用户或 * 不自动授予 Agent。owner Agent 同样 owner=false，仅可使用显式 eventAllow 工具白名单；不获得环境或资源访问，写调用仍需审批。代次重置与 grant 撤销即时生效；不继承发送方权限、不写入新 grant。父子通信地址仍绑定会话；不能保持原派出身份的跨成员或 Agent 追问，在写入子 inbox 之前明确拒绝，不能先给运行中的 owner 子任务注入文本再降权。两入口使用同一校验；原任务与原报告不被拒绝的输入污染。

需要用户本人输入的管理、写记忆等操作仍受原入口限制；Agent 回合只能只读本会话记忆。普通 send_message/send_file 不能把 Agent 回合输出发往 QQ/网页。自动子任务结果仍通过原报告格式交回父任务，不会直接通知 QQ。

## 文件

files 是发送方自己已授权工作区的路径列表，最多 5 个，单次总量不超过 10 MiB。宿主读取字节并冻结为来源 R2 资产；接收端验证来源证明和完整资产引用、哈希、大小，不另存接收方 R2 assets，而是以消息 ID + 附件序号生成稳定 operationId，经 saveAttachment 的独立只增附件提交路径（字节 + manifest/head + 原子成功回执）持久化到 /work/agent-files/<消息哈希>/。只在持久提交成功后入箱，目标可用既有 read 读取；接收、读取和转发附件不依赖 coding_exec。子任务即使未授 coding，也只能读取其 inbox 登记的附件。不能用裸跨 scope asset ID 或发送方路径代替副本。

同路径同 SHA 的 createOnly 原本就能以不同操作 ID 成功；不能据此声称随机 ID 必然冲突。附件现在不调用容器命令，不生成 failed/unknown/expired 命令回执；R2 或事务提交前失败可重新提交，head 与成功证明原子更新，不受命令 32 条结果窗口影响。

子会话验证来源与边授权后先查询既有 inbox：相同 ID/信封返回原 duplicate 回执，不重建或覆盖已编辑、已删除的附件；不同信封拒绝冲突。父状态同步失败仍可重试，但不重新导入文件。已回答报告遇到明确会话撤销/结束时沿用 cancelled 状态退休，不增加 reported 计数；投递未知或临时错误保留 answered 和心跳重试。

登录凭据禁止转发。已知凭据文件名和凭据文本模式在完整内容上检查，不先截断；模式检查不是对任意编码/加密文件内容的万能识别，模型仍须遵守不传凭据的约束。

自动汇报保留全文，同时移除原有 reportText 的 8000 字限制和新通道的提前截断；8000 字上限本身不是本 PR 新引入的回归。疑似凭据值明确替换为隐藏提示，不误标整个任务失败。凭据模式可能隐藏示例值，仍需人工阅读核验。

纯文本/报告的待投递证明也只存哈希，重放由相同输入哈希验证；附件发送冻结引用与正文。发送成功后仅保存输入哈希、信封哈希及回执，不保留完整正文。每个当前代次最多 512 个发送证明；达到上限返回 agent_history_full，旧调用仍可重放，需显式重置会话后才能回收旧代次。超过上限的旧版本历史在重置后分批回收，必要时重试当前发送。这里优先保持去重安全，不自动驱逐仍可能重放的证明；不是无限运行消息队列。

## 验证边界

本地测试使用 workerd/SQLite/R2 测试环境、faux 模型；工作区持久化用真实 WorkspaceManager/manifest/CAS，容器客户端使用测试夹具。它们验证源码链路，不等于真实 Cloudflare 容器、真实账号或线上群部署验收。发布前还需独立审查，并在另行授权的环境验证双方实际 read 文件及无 QQ 外泄。当前不得宣称线上可用。
