# 个人设备与持久 VM 的 Cua 接入

cs-agent 通过名为 `cua` 的反向 MCP 读取自托管的 Cua Spaces 目录。每台设备是一张卡片，含名称、Space ID、系统和上游报告的状态。模型调用 `list_spaces` 选机，再用该卡片的完整 ID 调用 `list_tools`，查询这台设备的 Driver 工具说明（`service=driver`）。本次开放的是这两个只读查询。需要运行命令、读写文件的任务可以使用会话的 Cloudflare 编码沙箱或已授权的 Windows Sandbox。[Windows Sandbox 接入](WINDOWS-MCP.md)

## 控制端与设备

| 位置 | 职责 |
| --- | --- |
| Cloudflare Worker | 托管对话、操作权限、MCP 工具目录与结果。现有反向 WebSocket 接受经过认证的 MCP 节点，管理台可查看注册节点的连接状态。 |
| 自建 VPS | 设计中部署 Static Mode Relay 和聚合 `cua daemon`。控制端保存每台设备的目录和独立凭据。聚合 MCP 仅供 VPS 本地访问，反向桥负责连接 Worker。 |
| Mac、Linux、Windows VM | 在设备侧运行 Cua 的设备服务和所需的 Driver。Windows 持久 VM 使用来宾内的交互用户。桌面可用性取决于用户登录状态和本机授予的权限。 |

静态模式需要核对设备身份。Cua SDK 0.31.0 按主机名和端口构造 `direct:<host:port>`。同一 Relay 的多个 URL 即便路径含有不同 machine ID，在聚合目录里仍可能得到同一个 ID，后登记的设备可能覆盖原端点。每台设备需要独立且稳定的内部主机名或端口，并将该地址和允许注册的设备身份绑定。换机时先撤回原分配，核对新设备身份后再授权。[Cua 0.31.0 的设备登记实现](https://github.com/trycua/cua/blob/cua-sdk-v0.31.0/libs/cua/crates/cua-spaces/src/spaces.rs#L1322-L1382)

公网入口只接受所需的设备注册流量。设备代理路径 `/m/<machine-id>/…` 和聚合 MCP 仅能从内部访问。设备与控制端凭据分开保存，按各自身份鉴权。管理台中的「节点在线」表示反向桥已连接 Worker。设备状态和 Driver 工具目录要从对应的 Space 查询。

## 会话分配与生产验收

主人在「权限与运维」中的「设备按会话分配（Cua）」为指定的 `group:<id>` 或 `private:<id>` 勾选设备。主人可查看整个目录，其他会话只能查询获准设备的卡片和 Driver 工具说明。子任务可查询的设备取派出时清单与当前分配的交集。设备目录授权只开放上述查询；普通第三方 MCP 和 WSB 的工具授权和审批单独配置。

上线前在至少两台可区分的测试机上逐项验收。

1. 在纯自托管配置下，确认控制端和设备都能运行。重启其中一台后核对两台的稳定 ID 和实际主机名，再核对旧身份无法接管新分配。
2. 在主人会话列出两台设备的名称、系统和完整 ID。分别查询 Driver 工具说明，对照设备自身的工具目录，核实响应确实来自选定设备。核查实际暴露的工具只有 `list_spaces` 和 `list_tools`。
3. 仅向一个测试会话分配设备 B。核对目录只显示 B，指定设备 A 的调用被拒。派发子任务后撤销 B，再核对其下一次调用被拒。
4. 中断桥接连接，验证设备目录不可查询、已有分配仍可撤回。恢复连接后重新读取目录，并核对普通 MCP、QQ 收发及 WSB。

上述步骤是生产切换前置条件。VPS 部署、两台真机的设备隔离和生产接入均待现场验收。

## 从旧设备服务切换

1. 升级前在旧管理台记录每台设备的名称、UUID、MCP 地址和 Tunnel/DNS 对应关系。结束旧任务、导出仍需的收据，检查定时任务及自定义技能中保存的旧工具名。用旧版管理台逐台撤销设备接入，确认旧路由返回 404。
2. 在设备上用原客户端和当时的登录账户运行 `node cs-agent-device.cjs remove-service`。使用自定义状态目录时提供原 `--state-dir`。停掉手工启动的进程。旧独立桌面及 Hyper-V 来宾可能另有 `CsAgentDesktopMcp`、`CsAgentHypervShellV1`、`CsAgentHypervDesktopV1` 计划任务，按实际安装情况停用。保留项目盘和需要的历史收据。
3. 对照升级前的清单，逐项删除只供旧设备使用的 Cloudflare Tunnel 和 DNS 记录、撤销其专用凭据。CS2 Workshop、WSB 或其他服务可能仍使用自己的 Tunnel。Cloudflare 账户管理使用独立授权。
4. 新版 Registry 初始化时清理旧配对表、工具别名，以及能与配对记录或旧桌面工具契约准确匹配的 MCP 记录。人工改名或改址的服务需由管理员核实。生产设备的自启动、外部脚本和 Cloudflare 资源都需单独清退。

升级会将服务 ID `cua` 保留给设备目录。如果旧版本已有同名 MCP，先记下其用途并使用其他 ID 重新配置。新版会清除旧 `cua` 的登记和凭据，管理员需要为目录桥重新登记并分配。

回退 Worker 只能恢复旧程序。恢复旧配对记录需要切换前的备份或重新登记。持久 VM 的磁盘由设备所有者管理，WSB 宿主机原有任务账本和环境 ID 保留。
