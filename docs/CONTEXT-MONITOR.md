# 上下文监控

管理端「会话对话」保留顶部 Agent 拓扑，在下方提供可折叠的上下文趋势。点击拓扑或左侧父子会话时，趋势跟随当前 agent 切换；父会话和子 agent 的模型请求不会混合统计。

## 页面如何使用

- 展开趋势后，按请求顺序查看输入 token、上下文窗口和缓存命中率，每组 10 次请求。空心点代表上游没有返回用量，不代表 0 token。点击请求点打开详情。
- 「上下文组成」用面积表示字符占比，区分系统提示、工具定义、历史摘要、用户消息、助手消息和工具结果。点击分类筛选，默认列出最大的 4 项，完整列表每页 10 项。
- 「前后变化」比较同一会话、同一 actor、同一用途的相邻请求。相同内容按指纹和出现次数配对；修改表现为移除旧内容并加入新内容。切换模型或重置会话时不计算输入 token 的变化率。
- 「压缩过程」展示选定范围、摘要生成和用于当前请求的时间，以及摘要、保留消息、新增消息的大小。压缩来自引擎的真实 `pi.compaction` 条目，不根据 token 下降推断。后续请求继续使用摘要时，不重复标为发生压缩。
- 「输出与工具」保留模型输出及调用后的工具执行详情；「原始快照」提供按需加载的原始记录。

## CodeMode 执行组

「输出与工具」把一次 CodeMode 作为一个执行组：折叠时显示实际内部工具的名称、次数、耗时和异常数；展开后按父调用 ID 展示调用树。时间条相对于整组开始时间，可重叠，不将并行调用画成顺序依赖。每层列表每页 10 项，脚本源码、内部参数及文本 / 结构化结果按需读取。

脚本捕获了内部错误后仍可能成功结束；执行组同时保留外层状态和内部异常数。未采集或已清理的记录不会伪装成成功。参数摘要先脱敏再截断，图片、音频及资源二进制保留占位，完整正文遵循原有截断和总容量限制。

上下文里的工具结果附有原执行组的摘要，可展开执行记录并定位发起调用的模型请求。关联使用会话、actor、回合、调用 ID 和时间，不从脚本字符串猜测工具；旧快照保留了调用 ID 且仍有追踪记录时也可关联。

主 agent 和子 agent 使用同一套工具追踪。子 agent 的回合 ID 包含自身身份和引擎输入 ID，续轮沿用同一回合，跟进任务另开回合。新增子 agent 工具记录复用 RequestsDO 的既有开始 / 结束写入；不增加模型调用、独立轮询或新 DO。

**内部工具结果不重复计入上下文。** 例如脚本读取 50,000 字符，只输出 500 字符，后续模型输入只计实际输出的部分；完整执行详情只供排查，字符和 token 统计不因此增加，也不会分摊虚构的工具 token。

## 统计口径

输入 token、输出 token、缓存读取量使用现有上游 usage，未上报时保持空值。缓存命中率为缓存读取 / 总输入，不能据此断言某段 system、工具定义或消息命中了缓存。

组成和逐项变化统计的是归一化快照文本的 JavaScript 字符长度，包含工具调用参数、工具返回文本及当前工具定义。图片和推理正文只计快照里的占位文本，不能与实际图片 token、隐藏推理或供应商序列化后的请求大小相等同。分类字符数不是逐段实测 token，也不会按总 token 比例伪造逐段 token。

正文仍遵循既有脱敏、每块截断、最近 100 条消息和整体正文上限；分类总量与逐项大小在截断之前计算。因此「36,000 字符，正文截断」表示模型上下文里这段可读文本的大小是 36,000，而管理端只保留其中一部分。凭据文本和二进制不会因新监控而扩大保存范围。

新版本的主、子 agent 在 `beforeRequest` 读取已提交的上下文来源，在 `beforeCompact` 记录最新一次范围选择。真实压缩条目出现在该次请求时才归类为历史摘要。范围选定后产生的消息单独统计；缺少压缩选择记录时显示「未采集」，不把未知阶段当作 0。

## 采集与查询边界

`captureModels` 继续通过既有 `RequestsDO.record()` 写入请求快照，新统计随同一份记录保存；不增加独立采集 RPC、Queue、DO 类型、容器或周期任务。执行 DO 仅保存一份小型压缩选择记录，用于重启后恢复分类，不存额外正文，也不修改模型输入、压缩策略或模型出站 alarm 流程。

管理端的趋势、分析和正文接口全部读取 RequestsDO：

| 接口 | 内容 |
| --- | --- |
| `GET /admin/context-timeline?thread=...&actor=...` | 当前 agent 的轻量趋势，按游标每次 10 项 |
| `GET /admin/requests/:id?summary=1` | 请求元数据和详情可用状态，不发送输入正文 |
| `GET /admin/requests/:id/context` | 分类、逐项大小及相邻请求差异，不发送正文 |
| `GET /admin/tools/:id/execution` | 执行组元数据及原模型请求 ID，不返回正文 |
| `GET /admin/tools/:id` | 按需读取单个工具参数、文本结果及结构化结果 |
| `GET /admin/requests/:id/context/:part` | 展开的系统提示、工具定义、单条消息或输出；工具调用按需携带已保留的配对结果 |

页面未展开趋势时不读取趋势；展开后复用已有活跃会话刷新，最多每 10 秒更新一次。空闲、后台页面、历史分组不新增轮询。请求正文只在展开时获取。

统计元数据沿用请求 30 天 / 20,000 条的保留边界，分析明细和正文共同计入既有 7 天 / 32 MiB 总容量。清理正文后仍可查看 token 趋势，但逐项对比会提示缺失。旧请求未采集的来源和逐项统计不会补造，可按需查看旧快照。

## 验证

`workers/test/context-monitor.test.ts` 覆盖截断前统计与脱敏、actor 隔离、重复消息配对、正文清理后保留趋势，以及主/子 scope 的真实 Harness 手动压缩与重开恢复。浏览器契约测试检查新增路由的实际返回结构。

CodeMode 的主、子执行链路由 `coding-tools.test.ts`、`subagent.test.ts` 验证；`tool-execution.test.ts` 覆盖多层调用、actor 隔离、历史结果回链、内部结果不进入上下文、结构化脱敏和正文清理。
